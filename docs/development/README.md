# Product direction and development conventions

These documents guide work on Tracer; they are not a feature checklist, certification claim or representative-user validation result.

- [Product vision and user needs](user-needs.md): sourced needs and evidence qualifications.
- [Journeys and candidate stories](user-journeys.md): task hypotheses, not implementation authorization.
- [UX direction](ux-plan.md): the shared Atlas workspace, selected interactions and open evaluation questions.
- [Development flow](development-flow.md): bounded slices, verification and independent validation.
- [Development model](development-model.md): Tracer's optional native dogfooding conventions and trace meanings.
- [Selected specifications](specifications/README.md): deliberately retained acceptance/reference material.
- [Private development register](register.md): local structured status, guarded updates and recovery.
- [Historical archive](archive.md): recovery of superseded plans, prototypes and engineering activity logs.

Start implementation from the current request and relevant maintained contracts, not a historical proposal or an authored status string. Use [Contributing](../../CONTRIBUTING.md) for setup/checks and [Architecture](../architecture.md) for source ownership.
