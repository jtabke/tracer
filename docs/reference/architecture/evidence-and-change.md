# Evidence and engineering change

## Distinct meanings

An entity may carry resource identity; a qualified relationship may carry a contextual reference. Reference role/selector/state, native annotation version and observed content are distinct. Observations record what was explicitly available or unknown; the application does not silently fetch bytes or reanchor passages to fill historical context.

Receipts capture declared inputs and an execution/analysis outcome. Reviews record separate immutable applicability judgments against a captured comparison. A source citation, structural link, fresh input, performed result and controlled conclusion are not interchangeable claims. Changed inputs do not rewrite an original outcome; unknown material is not accepted as known-current evidence.

## Application contracts

Version-pinned application-model descriptors bind project-defined roles and policies to native records. Server resolution checks the descriptor, governing schema and extra required fields. Stored record type/status fields alone do not establish controlled opening, execution or completion. [Model templates](../models/) illustrate bindings, not installed authority.

Change assessments capture an explicit baseline/current traversal or exact configuration pair, root, native/evidence basis and candidate population. Candidate judgments retain reasons, independent supporting uses and action obligations. Refresh is explicit and retains prior obligations; newly discovered work cannot disappear behind an earlier completion. Historical completion and current applicability are displayed separately. Controlled close/reopen commands, not editable status strings, own the lifecycle.

Verification captures exact requirement criteria, methods and basis; its target may be an explicit captured configuration or declared current-head policy. Activities retain performed observations/results. Explicit result accounting and applicable selected support precede a controlled scoped conclusion. A review cannot turn a failed result into a pass, ignore changed governing criteria or discharge unresolved unknowns. A conclusion is not organizational release approval.

## Configuration follow-through

Capture/comparison keeps exact identities independently of mutable names. Assessment preparation receives the displayed pair and explicit root. Verification handoff declares the after target. Completed follow-up actions select a genuine controlled conclusion for that target and scope, not a report label. Current head changes never replace either selected configuration.

Names are presentation metadata: readable record keys/names and exact configuration/baseline names belong in primary context; UUIDs remain in inspectable identity/provenance details. Failed name reads cannot substitute a newer capture or change authoring authority.
