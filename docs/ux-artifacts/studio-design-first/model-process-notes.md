# Model workflow study

Historical AI-assisted design exploration, superseded by the [shared map/workbench direction](../../ux-plan.md#shared-workspace). The [interactive study](model-process-study.html) rehearses schema editing using fictional project data; it is not a native schema migration or participant study.

## Design findings

- Separate development workflow order from stored trace direction. Verification can receive requirement criteria and a design-under-test through different recorded inputs.
- Keep one Model draft across visual, text and structured-property representations.
- Make selected type definitions readable, with a clear distinction between whole-process orientation and focused editing.
- Retain edits while moving between work and configuration; Cancel restores the prior definition.
- Adapt long definition editing and evidence reading to narrow layouts rather than compressing desktop sidebars.
- Keep scope recipes explicit. A preview of declared relationships does not create records or establish readiness.

Scripted checks exercised multiple fictional schemas, retained draft/label state, invalid JSON, cancellation and narrow geometry. Native persistence, broader fault handling and representative-user comprehension are separate evaluations.
