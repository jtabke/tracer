# Contribution-board read contract: QA checklist

**Status:** historical source audit and broad candidate acceptance cases, followed by an authorized bounded native working-context slice. The current [architecture contract](../../architecture.md#consistent-working-context-read) owns the selected limits/semantics; the [UX plan](../../ux-plan.md#selected-slice--mounted-working-context-for-authoring-and-change-review) owns the two task specifications. This does not select Alternative A or establish mounted UI completion.

New [native contract tests](../../../test/working-context.test.ts) and [HTTP/CLI contract tests](../../../test/working-context-http.test.ts) exercise the implemented slice. Distinct identities retain one deterministic path, not an exhaustive path population. Receipt totals cover focus and loaded rows, not a board-wide project census. Comparisons exceeding the per-response input budget remain explicitly unloaded. Durable recipe editing and mounted draft/navigation acceptance remain follow-up work. The tables below preserve the broader **preimplementation** audit and are not claims that every proposed case or browser task is delivered.

The read compares immutable receipt captures with current native records and latest explicit observations. It requires no named baseline. A project baseline would answer a different before/after question.

## Proposed acceptance cases

| ID                                   | Case and required evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A-QA-01 — exact scope                | Return the exact root identity, native/schema/evidence revisions, incoming `realized_by` selection and declared endpoint populations. Reverse direction, another allowed relationship, wrong endpoint type, removed root and undeclared relationship must not silently yield the same board. Reject missing current roots; exact old receipts remain independently readable. Do not infer “requirement” or “evaluation” roles from type names.                                                                                                                                                                                                                                                        |
| A-QA-02 — row/edge identity          | Exercise parallel membership links, a self-loop where permitted, shared intermediate definitions and a shared terminal output. Deduplicate rows by canonical row identity while retaining all recorded link IDs/directions. Distinguish membership-edge count, distinct row count, per-row route links, distinct intermediate identities and distinct terminal outputs. Board-wide unique receipt totals must not double-count a shared receipt displayed through two rows or paths.                                                                                                                                                                                                                  |
| A-QA-03 — complete branches          | Put qualifying context/result-route links after more than200 irrelevant incident links. Apply every selected relationship/direction/endpoint constraint before bounded retrieval. At every branch limit, return exact total and continuation/completeness or reject explicitly. An incomplete first or later route step is never a complete absence; a failed endpoint read is never an empty slot.                                                                                                                                                                                                                                                                                                   |
| A-QA-04 — all output results         | For one terminal output reached through the selected ordered route, record zero, one and several receipts, including unrelated captures before the matching one beyond a1000-record global prefix. Return the exact count of **all** output receipts, partitioned into focus-declared and unmatched captures. Multiple receipts keep distinct immutable IDs/outcomes; none becomes the valid receipt merely because it is newest. Output edits do not rewrite captured output versions.                                                                                                                                                                                                               |
| A-QA-05 — explicit focus dependency  | Match the root only when a receipt declares that terminal entity ID. A direct input and an input with an explicit captured path both qualify. Mere native reachability, output identity, a mention, an intermediate path endpoint or a captured configuration member not declared as an input does not qualify. A link-only reverse-index match must not be presented as a declared focus entity. Verify returned index matches against receipt JSON, the capture authority. Index completeness comes from transactional backfill/append and their regression checks; this is not a promise to detect administrator tampering through a whole-database audit on every read.                           |
| A-QA-06 — truthful absence/filter    | A reached terminal output with only unmatched receipts still has results. A “captured this focus” filter may hide those cards only with an exact unmatched count and a route back. A receipt append or changed filter cannot retain a stale zero-result label. Keep separate states for no first route link, intermediate definition/no terminal link, terminal output/no receipt, unmatched receipt, incomplete page and unavailable read.                                                                                                                                                                                                                                                           |
| A-QA-07 — comparison scope           | Return root-input state separately from full receipt state. Test root fields unchanged while another declared input changes, selected-field equality despite a newer native version, unselected annotations, historical/configuration pins, changed selected dependency links and removed path links. Review judgments concern the full declared comparison; a root-only badge must not mask other input drift. Captured content and outcomes remain exact.                                                                                                                                                                                                                                           |
| A-QA-08 — unknown and changed        | Test deleted current input, missing/latest-unknown external observation, unknown original observation followed by an available observation, and matching hashes despite different timestamps/commits. Original unknown captures never become known retrospectively. Unknown and changed may both be true; retain both flags even when the display state is `unknown`. Declare whether summary counts classify display states exclusively or count independent flags; never imply the latter sum to the number of inputs. A missing active topology endpoint is an integrity error, distinct from a receipt input legitimately deleted after capture. No read observes external content automatically. |
| A-QA-09 — review clock/applicability | Latest review means highest append sequence, not timestamp or first page. Include more than1000 older reviews, a newer matching accepted/acknowledged/reevaluation decision, and a newer nonmatching review token. The latter yields unreviewed current applicability with the previous review disclosed; do not revive an older matching decision. Relevant input drift invalidates applicability; unrelated native/evidence changes leave the scoped comparison token unchanged. An accepted review does not clear drift; unknown inputs cannot be accepted under the existing write contract.                                                                                                      |
| A-QA-10 — supersession               | Include original receipts, several direct superseding receipts and a supersession chain; some replacements deliberately omit the root. All remain readable/countable. Supersession is separate from freshness, review and result validity. Return exact supersession counts with explicitly bounded samples/pages; do not expand the legacy unbounded `supersededBy` list into every board card.                                                                                                                                                                                                                                                                                                      |
| A-QA-11 — coherent continuation      | Bind each continuation to the full data scope/filter, pagination kind/parent, native head, schema version and evidence sequence. Test membership/endpoint/attribute/schema edits and every evidence append kind: receipt, review, observation and external binding, including unrelated appends and review-only changes with unchanged native head. Restart on stale context; never merge rows/counts from different contexts. Wrong-root/filter/output/branch cursors reject. Validate malformed/oversized cursor envelopes before stale-context checks. Lens changes alone are presentation and should retain the data scope.                                                                       |
| A-QA-12 — failure and no writes      | Inject SQL/read failure, busy/transaction failure, unavailable topology endpoint and inconsistent captured lookup. Fail the response explicitly rather than returning a partial board marked complete. Preserve the last labelled snapshot for reading, pause affected writes and require authoritative refresh. Assert native head/history, evidence sequence and every immutable payload remain unchanged after successful and failed reads.                                                                                                                                                                                                                                                        |

## Bounds that must be settled in the owning contract

### Cross-industry route case

The [fresh fixture audit](cross-industry-read-audit.json) supersedes direct-check-output lookup as a generic discovery assumption. Orbit uses `evaluated_by` directly to an evaluation output; Aster uses `verified_by → executed_as`, and Gatherline uses `checked_by → exercised_as` to run outputs. Apply A-QA-04–10 to **terminal outputs reached through the selected ordered route**, not automatically to the first definition. Test shared intermediates/outputs, parallel paths, a broken step, definition/no run, run/no receipt, incoming steps and distinct verification/validation purposes. A fixed route terminates at its declared final step even with cycles; no arbitrary graph reachability or type-name heuristic supplies another route.

The three Aster row appearances reach two unique check/run identities and two receipts, none declaring focused CMP-05. Gatherline reaches a RUN-TECH-02 receipt whose WORK-03 input is current while its full comparison is changed. Both remain inspectable results. These are necessary cross-domain oracles, not evidence that the candidate projection or task composition is implemented. The [prospective interaction contract](implementation-contract.md) owns route selection and truthful intermediate states; [read feasibility](read-contract.md) owns the current source mapping.

A coherent response needs explicit limits for membership edges/distinct rows, per-row context/result-route branches, unique terminal outputs, receipt cards and total captured-input/path comparison work. For **each chosen limit**, acceptance must include zero, exactly the limit and limit+1, with shared identities/parallel links that stress the distinction. No limit may turn omitted results into absence.

Existing bounds are evidence, not automatic choices for A: Family max20 membership edges/200 incident links; ordinary connections max50 per page; receipt capture max100 inputs and max100 links per declared path; Graph max50 receipts/200 declared inputs; Impact max25 receipts and200 declared inputs per response. A has no selected numeric budgets yet. Count/summary scope must state whole filtered scope versus current page, and receipt samples must disclose exact totals independently of returned cards.

Compare each page and full paged union with a complete isolated-fixture oracle. Check order, IDs, row/edge deduplication, totals and filter partitions. Storage-plan acceptance must show endpoint and output/dependency index lookups before limits, avoiding a global receipt census or deserialization of unrelated captures. Bounded response cardinality is not a fixed byte, SQL-work or latency guarantee; large fields and long captured paths need an explicit budget policy.
