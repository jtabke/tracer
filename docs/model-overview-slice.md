## Design adaptation and rationale

Historical choice, now visually rejected: advisor option 1 used a type atlas plus textual directed relationship register. Treating diagrammatic representation as decorative was the wrong constraint: PN-03 requires comprehensible relationships, and a meaningful type diagram can convey them without inferring tiers. This paragraph records the previous implementation, not current design guidance. Fields expand through native details; no badges or new aggregate infrastructure. Retained Workspace entry and contextual family editor for authoring (PN-02/09).

Initially selected the advisor's IDs-only fallback. Round 1 reproduced the recognizable-identity failure in both domains; replaced it with the advisor's bounded endpoint-summary projection, not browser N+1 hydration or a project census. Only current-page endpoint key/title/type is projected; missing items are explicitly unavailable. Canonical IDs and guarded inspection remain. Type return restores its action focus; relationship Back restores its row focus. Recorded data appears below the complete register rather than replacing the declaration inventory, retaining model orientation; narrow layouts stack labeled direction rows. Native CSS tokens/controls retained.
